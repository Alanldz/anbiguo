# 07 · 项目管理与协作规范

## 一、分支模型

| 分支 | 用途 | 来源 | 合并去向 |
| --- | --- | --- | --- |
| `main` | 生产环境代码，只接受经测试的合并 | — | 部署 |
| `develop` | 集成分支，日常合并目标 | `main` | `main` |
| `feature/xxx` | 功能开发 | `develop` | `develop` |
| `fix/xxx` | 缺陷修复 | `develop` | `develop` |
| `hotfix/xxx` | 线上紧急修复 | `main` | `main` + `develop` |
| `release/v1.0.0` | 发版冻结 | `develop` | `main` |

分支命名用**英文 + 连字符**：`feature/bank-import`、`fix/exam-timer-pause`。

## 二、提交规范（Conventional Commits）

```
类型(范围): 简短描述

可选正文：说明为什么改、影响范围
可选脚注：关联需求 ID / 接口编号，如 Refs: API-BANK-002
```

| 类型 | 含义 | 类型 | 含义 |
| --- | --- | --- | --- |
| `feat` | 新功能 | `refactor` | 重构（不改行为） |
| `fix` | 修复缺陷 | `perf` | 性能优化 |
| `docs` | 文档变更 | `test` | 测试相关 |
| `style` | 格式调整 | `chore` | 杂项/依赖 |
| `build` | 构建/部署 | `revert` | 回滚 |

示例：

```
feat(bank): 支持 Excel 批量导题

Refs: API-IMP-001, API-IMP-002
```

**提交前自检**：无 `console.log` / `var_dump`；命名符合 `02` 文档；接口已在 `04` 登记；新表已在 `03` 登记。

## 三、评审流程

1. 开发完成 → 本地自测通过 → 推送分支
2. 发起合并请求（MR/PR），填写：变更内容、影响范围、自测结论、关联接口/表编号
3. **至少 1 人评审通过**方可合并；涉及数据库变更、支付、权限的需 2 人
4. 合并前确保：无冲突、CI 通过、文档已同步更新
5. 合并后删除功能分支

### 评审检查清单

- [ ] 命名是否符合 `02-代码命名规范.md`
- [ ] 是否有硬编码的 KEY / 域名 / 密钥
- [ ] 新表 / 新字段是否已登记到 `03`
- [ ] 新接口是否已登记到 `04`
- [ ] 新 OSS 目录是否已登记到 `05`
- [ ] 新后台页面是否已登记到 `06`
- [ ] 是否有 SQL 注入 / 越权 / 未鉴权风险
- [ ] 是否有敏感信息写进日志

## 四、环境与发布

| 环境 | 用途 | 域名示例 | 数据 |
| --- | --- | --- | --- |
| 本地 local | 开发调试 | — | 本地库 |
| 测试 test | 联调与测试 | `api-test.xxx.com` | 脱敏测试库 |
| 预发 pre | 上线前验收 | `api-pre.xxx.com` | 生产数据副本（脱敏） |
| 生产 prod | 正式环境 | `api.xxx.com` | 生产库 |

发布流程：

```
① 从 develop 拉 release/vX.Y.Z → 冻结
② 部署测试环境 → 测试验收（对照验收清单）
③ 部署预发 → 产品验收
④ 合并 main → 打 tag（vX.Y.Z）→ 部署生产
⑤ 观察 30 分钟核心指标（错误率、接口耗时、支付成功率）
⑥ 回滚预案：保留上一版本包 + 数据库变更可逆脚本
```

## 五、数据库变更流程

1. 写 migration 文件（`server/database/migrations/YYYY_MM_DD_HHMMSS_描述.php`）
2. 文件名描述用小写下划线：`2026_09_15_120000_create_bank_question_banks_table.php`
3. 同步更新 `03-数据库设计规范.md` 数据字典登记表
4. 提交评审（至少 2 人）→ 在测试库执行 → 验证数据 → 生产执行
5. 生产执行前**必须备份**：`mysqldump` 全库或该表
6. 变更记录写入 `03` 文档「变更登记」表

## 六、文档同步责任

| 变更内容 | 必须更新的文档 |
| --- | --- |
| 新增/修改接口 | `04-API接口规范与登记表.md` |
| 新增/修改表结构 | `03-数据库设计规范.md` |
| 新增 OSS 目录 / 文件类型 | `05-OSS存储与文件分类规范.md` |
| 新增后台页面 / 权限点 | `06-后台隔离与权限设计.md` |
| 新增页面 / 分包（前端） | `01-技术架构与选型.md` 页面清单 |
| 技术选型调整 | `01` + `00` 决策表 |
| 规范本身变更 | 对应文档 + `CHANGELOG.md` |

## 七、代码质量工具（建议）

| 语言 | 工具 | 配置 |
| --- | --- | --- |
| PHP | PHP-CS-Fixer / PHPStan | PSR-12；静态分析 level 6 |
| TypeScript | ESLint + Prettier | airbnb-base + vue3 规则 |
| 样式 | Stylelint | 标准配置 |
| 提交 | commitlint + husky | 校验提交信息格式 |
| 前端 | vue-tsc | 类型检查 |

## 八、接口联调约定

- 后端先提供 **Mock 数据**（按 `04` 文档响应结构返回），前端不等后端开工
- 联调以测试环境为准，禁止直连生产库调试
- 联调问题记录在缺陷清单，修复后回归验证

| 第五步 | 第三方接口模块、配置中心、接口变更登记 |
