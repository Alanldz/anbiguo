# 03 · 数据库设计规范

> 引擎 InnoDB，字符集 `utf8mb4`，排序规则 `utf8mb4_unicode_ci`。
> **每一张表建完后，必须在本文件「数据字典登记表」中登记，否则视为未完成。**

## 一、命名规范

### 1.1 表名

- 全小写 + 下划线，**复数**形式：`questions`、`question_banks`、`exam_records`
- 模块前缀（用于区分归属，便于权限隔离与维护）：

| 前缀 | 归属 | 示例 |
| --- | --- | --- |
| `user_` | 用户域 | `user_accounts`、`user_wrong_questions` |
| `bank_` | 题库域 | `bank_categories`、`bank_question_banks` |
| `question_` | 题目域 | `question_items`、`question_options` |
| `exam_` | 考试域 | `exam_papers`、`exam_records` |
| `order_` | 交易域 | `order_orders`、`order_payments` |
| `file_` | 文件域 | `file_assets`、`file_categories` |
| `content_` | 内容 / 运营域 | `content_banners` |
| `sys_` | 系统域 | `sys_admins`、`sys_configs`、`sys_logs` |

> 关联表用「主表A_主表B」小写下划线：`user_favorite_questions`。
>
> **为什么不把运营位放 `sys_`**：客户端需要读取 Banner，而 `sys_` 表对客户端数据库账号**零授权**（见 `06` §二）。
> 只要一张表需要被客户端或用户后台读取，就必须落在业务域前缀下，绝不能是 `sys_`。

### 1.2 字段名

| 类型 | 规范 | 示例 |
| --- | --- | --- |
| 主键 | 统一 `id`，`bigint unsigned auto_increment` | `id` |
| 外键 | `关联表单数_id` | `question_bank_id`、`user_id` |
| 布尔 | `is_` 前缀，`tinyint(1)` | `is_vip`、`is_deleted` |
| 状态 | `status`，`tinyint` + 注释枚举含义 | `status` |
| 时间 | `_at` 后缀，`datetime` | `created_at`、`deleted_at` |
| 金额 | `_amount` 后缀，`decimal(10,2)` | `pay_amount` |
| 计数 | `_count` 后缀 | `question_count` |
| 排序 | `sort_order`，`int`，越小越靠前 | `sort_order` |
| 标题/名称 | `title` / `name` | `title`、`nickname` |
| JSON 扩展 | `_json` 后缀 | `options_json`、`extra_json` |

### 1.3 必备字段（所有业务表）

```sql
`id`          bigint unsigned NOT NULL AUTO_INCREMENT COMMENT '主键',
`created_at`  datetime DEFAULT NULL COMMENT '创建时间',
`updated_at`  datetime DEFAULT NULL COMMENT '更新时间',
`deleted_at`  datetime DEFAULT NULL COMMENT '删除时间（软删除）',
PRIMARY KEY (`id`)
```

> 用户可见数据一律**软删除**；`sys_logs`、`exam_records` 等流水表可物理存储不做软删。

### 1.4 索引规范

| 类型 | 命名 | 示例 |
| --- | --- | --- |
| 普通索引 | `idx_表名_字段` | `idx_questions_bank_id` |
| 唯一索引 | `uk_表名_字段` | `uk_user_accounts_mobile` |
| 联合索引 | `idx_表名_字段1_字段2` | `idx_exam_records_user_id_created_at` |
| 外键约束 | 不使用物理外键，靠应用层保证 + 索引提速 | — |

- 联合索引**最左前缀**：等值条件在前、范围条件在后
- 单表索引数量 ≤ 6 个；区分度低的字段（如 `status`）不单独建索引
- 所有外键字段必须建索引

### 1.5 设计红线

1. 禁止 `SELECT *`，禁止无 `WHERE` 的 `UPDATE` / `DELETE`
2. 禁止在数据库存明文密码、明文密钥、明文身份证
3. 单表字段数 ≤ 40；大文本（题目解析、文档内容）用 `text`/`longtext` 或独立附表
4. 金额不用 `float`，用 `decimal`
5. 状态值不写魔法数字，必须用 `app/Enums/` 中枚举类统一管理，并与本文档注释一致
6. 表结构变更一律通过 migration，禁止手工在数据库上改

| migration 文件 | 覆盖表 |
| --- | --- |
| `2026_09_15_000001_create_user_domain_tables.php` | 用户域 8 张 |
| `2026_09_15_000002_create_bank_domain_tables.php` | 题库域 3 张 |
| `2026_09_15_000003_create_question_domain_tables.php` | 题目域 4 张 |
| `2026_09_15_000004_create_exam_domain_tables.php` | 考试域 4 张 |
| `2026_09_15_000005_create_order_domain_tables.php` | 交易域 3 张 |
| `2026_09_15_000006_create_file_domain_tables.php` | 文件域 2 张 |
| `2026_09_15_000007_create_content_domain_tables.php` | 内容域 1 张 |
| `2026_09_15_000008_create_sys_domain_tables.php` | 系统域 8 张 |

> **为什么按域分文件而非一表一文件**：本项目是「模块化单体」，同域表的变更通常同步发生，
> 按域聚合可让变更评审更聚焦；表级粒度仍由文件内的 `Schema::create` 保证，可单独回滚。
> 域内新增表时在本域文件末尾追加，并在 `down()` 中按逆序补 `dropIfExists`。
