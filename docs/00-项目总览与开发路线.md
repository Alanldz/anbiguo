# 00 · 项目总览与开发路线

## 一、项目定位

面向考证/刷题人群的多端在线刷题平台。核心能力：**用户自有资料一键生成题库 → 多端随时随地刷题 → 考试与数据复盘**；同时具备官方题库市场、会员订阅与内容创作者变现能力。

产品功能范围详见根目录 `刷题软件功能清单.md`（15 个模块）。

## 二、总体开发路线（六步，含前置第 0 步）

> 用户确认的五步为主线，第 0 步为本次新增前置步骤，用于先立规范再写代码，避免后期返工。

### 第 0 步 · 地基：开发文档体系与命名规范 ★ 进行中

- 建立 `docs/` 开发文档体系（本目录）
- 确定技术选型与工程目录结构
- 明确代码命名规范、数据库命名规范、接口规范、OSS 分类规范、后台隔离规范
- **交付物**：`docs/` 全部文档 + 工程骨架目录

### 第一步 · 多端前端页面开发

- 一套代码多端兼容：**微信小程序 + Android APP（可后续直接封装 APK）+ H5**
- 按功能清单实现页面：首页、题库市场、我的题库、题库详情、AI 导题、练习答题页、考试页、我的
- 建立组件库与设计变量（颜色/字号/间距），保证多端视觉一致
- **交付物**：`client/` 前端工程 + 页面清单与路由登记表（写入 `01` 文档）

### 第二步 · 数据库设计与数据字典

- 依据功能清单完成 MySQL 表结构设计
- 严格遵循 `03-数据库设计规范.md`
- 所有表、字段、索引、注释**同步登记进数据字典表**
- **交付物**：建表 SQL（`server/database/migrations/`）+ 数据字典（写入 `03` 文档）

### 第三步 · 后端开发（PHP + MySQL，前后端分离）

- 严格 PHP + MySQL，接口驱动，前端零耦合
- 用户上传文档（Word/Excel/PDF/TXT/图片）解析入库，原文件归类上传 OSS
- 文件分类管理：按业务归属、类型、时间建立目录体系
- **交付物**：`server/` 后端工程 + 接口实现 + OSS 接入

### 第四步 · 双后台搭建（严格隔离）

- **总后台**（系统管理员）：目录、域名、部署、鉴权、数据库账号**完全独立**
- **用户后台**（电脑端 console）：用户自助管理题库、资料、订单、会员
- 两个后台目录分开，总后台独立部署，互不依赖
- **交付物**：`admin/`（总后台，独立）+ `console/`（用户后台）

### 第五步 · API 接口体系与配置中心

- 第三方接口接入：短信、微信小程序、微信支付、OSS、OCR/AI 导题等
- 所有 KEY / Secret / 模板 ID 支持**后台可视化配置与随时修改**，不写死在代码
- 每个接口在 `04` 文档登记（编号 / 路径 / 入参 / 出参 / 错误码 / 负责人 / 变更记录）
- **交付物**：接口层 + 配置中心 + 接口台账

## 三、里程碑与依赖关系

```
第0步 规范地基
   └─> 第一步 多端前端页面 ──┐
                             ├─> 第三步 后端开发 ──> 第五步 接口体系
       第二步 数据库设计 ────┘                          ↑
                                   第四步 双后台 ──────┘
```

- 第一步与第二步可**并行**（页面用 Mock 数据先行）
- 第三步依赖第二步的表结构，接口联调依赖第五步的配置中心
- 第四步的用户后台依赖第三步已有接口

## 四、当前范围界定

- 本次先做**功能清单确认 → 前端页面 → 数据库 → 后端 → 双后台 → 接口**
- 暂不启动：付费题库采购、运营活动、创作者分成结算（列为后续迭代）
- MVP 范围以 `刷题软件功能清单.md` 文末汇总为准
