# 06 · 后台隔离与权限设计

> 核心要求：**总后台完全独立**——目录、域名、部署、鉴权、数据库账号全部隔离，与客户端/用户后台零共享。
> 即使客户端或用户后台被攻破，也无法横向进入总后台。

## 一、三端角色界定

| 端 | 使用者 | 入口 | 核心职责 |
| --- | --- | --- | --- |
| 客户端 | 普通用户 | 微信小程序 / Android / H5 | 刷题、导题、考试、购买 |
| 用户后台（console） | 普通用户（电脑端） | `console.xxx.com` | 管理自己的题库、资料、订单、会员 |
| 总后台（admin） | 系统管理员 / 运营 / 客服 | `admin.xxx.com` | 平台级配置、审核、运营、数据 |

## 二、物理隔离方案（硬约束）

| 隔离维度 | 客户端 API | 用户后台 | 总后台 |
| --- | --- | --- | --- |
| 代码目录 | `server/` | `server/` | **`admin/`（独立工程）** |
| 部署目录 | `/www/wwwroot/app-server` | `/www/wwwroot/app-console` | **`/www/wwwroot/app-admin`** |
| 域名 | `api.xxx.com` | `console.xxx.com` | **`admin.xxx.com`** |
| 路由前缀 | `/api/v1` | `/console-api/v1` | **`/admin-api/v1`** |
| 鉴权守卫 | `auth:client` | `auth:console` | **`auth:admin`** |
| Token 签名密钥 | `JWT_SECRET_CLIENT` | `JWT_SECRET_CONSOLE` | **`JWT_SECRET_ADMIN`（独立）** |
| Token 有效期 | 7 天（可刷新） | 2 小时（无刷新，重新登录） | **30 分钟（无刷新）** |
| 数据库账号 | `app_client` | `app_console` | **`app_admin`** |
| 数据表权限 | 业务表读写（无 `sys_` 权限） | 仅本人数据 | 全部表 |
| 访问限制 | 公开 | 公开（HTTPS） | **IP 白名单 / VPN / 二次验证** |

### 数据库权限隔离（必须执行）

```sql
-- 客户端账号：只能读写业务表，禁止访问系统表
GRANT SELECT, INSERT, UPDATE, DELETE ON `anbiguo`.`user_%`   TO 'app_client'@'%';
GRANT SELECT, INSERT, UPDATE, DELETE ON `anbiguo`.`bank_%`   TO 'app_client'@'%';
GRANT SELECT, INSERT, UPDATE, DELETE ON `anbiguo`.`question_%` TO 'app_client'@'%';
GRANT SELECT, INSERT, UPDATE, DELETE ON `anbiguo`.`exam_%`   TO 'app_client'@'%';
GRANT SELECT, INSERT, UPDATE, DELETE ON `anbiguo`.`order_%`  TO 'app_client'@'%';
GRANT SELECT, INSERT, UPDATE, DELETE ON `anbiguo`.`file_%`   TO 'app_client'@'%';
-- 禁止：sys_% 相关任何权限

-- 用户后台账号：同样禁止 sys_ 表
GRANT SELECT, INSERT, UPDATE, DELETE ON `anbiguo`.`user_%` TO 'app_console'@'%';
-- （其余业务表同上，同样排除 sys_%）

-- 总后台账号：全表权限
GRANT ALL PRIVILEGES ON `anbiguo`.* TO 'app_admin'@'%';
```

> 客户端与用户后台账号**永远拿不到 `sys_configs`、`sys_admins`、`sys_logs` 的权限**，从数据层阻断越权读取密钥。

## 三、总后台目录结构（完全独立）

```
admin/
├── api/                          # 后端（独立框架入口，不 require server/ 任何文件）
│   ├── app/
│   │   ├── Http/Controllers/V1/  # AuthController / UserController / ConfigController ...
│   │   ├── Http/Middleware/      # AdminAuthMiddleware / IpWhitelistMiddleware / OperationLogMiddleware
│   │   ├── Models/               # 管理端模型（可复用表，但独立定义）
│   │   ├── Services/
│   │   └── Support/
│   ├── config/
│   ├── routes/admin.php          # /admin-api/v1/*
│   └── .env                      # 独立配置（独立数据库账号、独立密钥）
│
└── web/                          # 前端（独立工程）
    ├── src/
    │   ├── views/                # 页面：用户管理 / 题库管理 / 审核 / 配置中心 / 订单 / 日志
    │   ├── api/
    │   ├── components/
    │   ├── stores/
    │   └── router/
    └── vite.config.ts
```

## 七、权限模型（RBAC）

- `sys_admins`（管理员） —— `sys_roles`（角色） —— `sys_permissions`（权限点）
- 权限点命名：`模块:资源:动作`，如 `bank:question-bank:audit`、`sys:config:update`
- 预置角色：超级管理员（全部）、运营（内容/运营，无系统配置）、客服（用户/订单，只读为主）、财务（订单/对账）
- 前端菜单按权限点动态渲染；后端接口**二次校验**，不做纯前端隐藏
- 敏感操作（改配置、改权限、退款、封禁）需**二次确认 + 强制写日志**

## 八、安全加固清单

1. 总后台独立域名，不对外公开入口；登录页不含注册入口
2. IP 白名单 + 可选的二次验证（TOTP / 短信）
3. 登录失败 5 次锁定 15 分钟，记录登录日志（IP、UA、时间、结果）
4. 所有写操作写 `sys_logs`（操作人、模块、动作、前后值、IP、时间）
5. 配置中心敏感值 AES-256 加密存储，界面脱敏显示（`sk_****f3a1`）
6. 总后台与用户后台的**登录态互不通用**，Token 不能跨端使用（守卫 + 独立密钥双重保证）
7. 定期审计：管理员账号清单、权限变更、密钥轮换记录
